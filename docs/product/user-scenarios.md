# Пользовательские сценарии

Документ описывает подтверждённые пользовательские сценарии, видимые по SwiftUI-flow и view model логике. Это не продуктовая стратегия и не список будущих требований.

## Основной расчёт

Актор: пользователь приложения.

Предусловия:

- приложение запущено;
- открыт основной экран `MainView`.

Сценарий:

1. Пользователь вводит стартовый капитал.
2. Пользователь выбирает регулярность пополнений: без пополнений, ежемесячно, ежеквартально или ежегодно.
3. Если регулярность не `none`, пользователь может ввести размер пополнения.
4. Пользователь вводит срок инвестирования и выбирает единицу срока: годы или месяцы.
5. Пользователь вводит годовую процентную ставку.
6. Пользователь нажимает кнопку расчёта.
7. Приложение скрывает фокус ввода, валидирует обязательные поля и срок.
8. При валидном вводе приложение показывает ключевые показатели, график и помесячную детализацию.
9. Приложение пытается сохранить исходные параметры расчёта в историю.

Подтверждённые ошибки:

- если отсутствует стартовый капитал, срок или годовая ставка, результат сбрасывается;
- если срок меньше или равен нулю, результат сбрасывается;
- если сохранение в историю падает, пользователь видит ошибку истории.

## Просмотр результата

После успешного расчёта пользователь видит:

- внесённую сумму;
- итоговый капитал;
- заработанный процент;
- доходность;
- график роста капитала по месяцам;
- помесячную детализацию капитала.

Точный состав UI-компонентов находится в `Flows/Main/Views` и `Flows/Chart`.

## Экспорт PDF

Актор: пользователь с рассчитанным результатом.

Сценарий:

1. Пользователь запускает экспорт результата из блока результата.
2. Приложение отправляет аналитическое событие `result_export_started`.
3. `MonthlyCapitalPDFDocument` формирует PDF с таблицей помесячного капитала.
4. Передача файла выполняется через системный механизм `Transferable`.

Ограничение: документированный PDF содержит месяц и капитал. В найденной реализации нет подтверждения, что PDF включает исходные параметры расчёта или ключевые показатели.

## История расчётов

Актор: пользователь, у которого доступно локальное хранилище истории.

Сценарий просмотра:

1. Пользователь нажимает кнопку истории в навигации основного экрана.
2. Приложение отправляет событие `history_opened`.
3. `HistoryViewModel` загружает записи через `HistoryRepository.loadAll()`.
4. Если записей нет, отображается empty state.
5. Если записи есть, отображается список от новых к старым.

Сценарий повторного применения:

1. Пользователь выбирает запись истории.
2. `HistoryViewModel` передаёт запись в `MainViewModel`.
3. `MainViewModel` заполняет исходные параметры выбранными значениями и сбрасывает текущий результат.
4. Приложение отправляет событие `history_entry_reused`.
5. Экран истории закрывается.

Сценарий удаления:

- пользователь может удалить одну запись через swipe action;
- пользователь может удалить все записи через кнопку удаления и confirmation dialog;
- при ошибке удаления отображается сообщение ошибки истории.

## Дедупликация истории

При сохранении валидного расчёта SwiftData-репозиторий проверяет записи за локальный день расчёта. Если за этот день уже есть эквивалентный `CalculationInput`, новая запись не создаётся.

Эквивалентность проверяется по нормализованному вводу: `monthlyContribution` приводится к `contributionAmount`, поэтому `nil` и нулевое пополнение могут считаться одинаковым значением при соответствующей регулярности.

## Недоступная история

Если SwiftData-репозиторий не создаётся при запуске приложения, используется `UnavailableHistoryRepository`.

Подтверждённое поведение:

- основной расчёт остаётся доступным;
- `MainViewModel.isHistoryAvailable` возвращает доступность из репозитория;
- при недоступной истории `MainView` не показывает кнопку перехода в историю;
- пользователю может быть показана ошибка истории.
